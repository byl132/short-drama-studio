# 评测用例说明

这些用例描述「Skill 应该能做什么」，用于人工或 Agent 回归，不是自动化断言。自动化断言见 `run_evals.py`。

## CASE-01 一句话创意

输入：「一个外卖员在暴雨夜送错最后一单，发现收件人已经去世三年。」

预期：

- 先区分事实/偏好/假设/未决问题；
- 给出 3 条差异明显的故事路径，而不是直接写完整剧本；
- 只问会改变剧情的关键问题；
- 不伪造场景图或角色图。

## CASE-02 已有完整剧本

输入：一份 3 集短剧本。

预期：

- 进入剧本医生/拆解模式，不重启剧情；
- 输出 SCRIPT FACT / INFERENCE / DESIGN / OPEN QUESTION；
- 建立资产总表与场次—资产矩阵；
- 角色、场景、道具去重；
- 不为了生成画面改写剧本事实。

## CASE-03 局部改镜

输入：「把第 2 集结尾的回头改成不回头，直接关灯。」

预期：

- 只改指定镜头与结尾；
- 说明对因果、节拍和连续性的影响；
- 记录 SCRIPT DIFF；
- 列出受影响的资产与需要重新 QC 的镜头。

## CASE-04 只做诊断

输入：「看看我的分镜为什么节奏拖沓。」

预期：

- 只交付问题证据、优先级和最小修复；
- 不生成空白 CSV、不建完整生产目录；
- 不强行推进到生成阶段。

## CASE-05 要求直接生成视频

输入：「帮我把这集直接生成成片。」

预期：

- 先声明模型能力、预算与授权档（plan-only / single-test / approved-batch）；
- 未获授权不提交付费任务；
- 未实际调用时标注「待生成」，不声称已产出；
- 按门禁顺序先做高风险段样片。

## CASE-06 多人对白

输入：「两个角色在码头争吵，检票员插话。」

预期：

- 每句记录 speaker_id 与嘴型主体；
- 非说话者保持闭嘴与倾听反应；
- 错人开口/串声/非说话者同步嘴型判 P0；
- 给出口型不稳时的保护方案。

## CASE-07 长篇小说改编

输入：「这是 30 万字小说，帮我做成 20 集短剧。」

预期：

- 先抽样快评，再决定是否整本拆解；
- 建立章节索引与分层记忆；
- 伏笔有回收或弃用说明；
- 默认每批 1–3 集，先做样片。
