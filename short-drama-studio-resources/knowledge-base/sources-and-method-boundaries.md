# 资料来源与方法边界

这份知识库规定短剧生产中“依据什么、如何转换、何时停止”。它不是法律意见，也不保证某个成片在所有国家、平台或商业场景下都没有权利风险；涉及真人、商业发布、品牌、音乐、声音克隆或换脸时，仍需由项目负责人核验授权和当地规则。

## 一、资料来源分级

| 等级 | 资料类型 | 适合回答的问题 | 使用方法 |
|---|---|---|---|
| S1 | 用户明确设定、项目原始素材、已签署授权 | 这个人物是谁、能否使用、项目要表达什么 | 作为项目事实；记录来源和授权，不用通用知识覆盖 |
| S2 | 法律法规、平台政策、模型/软件官方文档、行业标准 | 能不能发布、当前工具支持什么、参数含义是什么 | 优先核对原文、版本和生效/访问日期；变化快的内容不写死 |
| S3 | 出版物、作者或出版机构页面、学术/专业课程、可靠行业资料 | 叙事、视觉结构、剪辑、声音和提示词方法 | 只提炼概念、方法和字段；书目与版本写入来源日志 |
| S4 | 公开提示词案例、社区教程、创作者分享 | 了解提示词组织方式和常见失败模式 | 只借鉴结构和可观察变量；必须原创改写并标注“案例启发” |
| S5 | 搜索摘要、转载、匿名帖子、模型生成的“资料” | 发现检索线索 | 不能单独作为事实依据；必须回溯到 S1–S3 或标为未核验 |

用户的明确创作意图优先于审美建议；官方当前文档优先于过期经验；项目授权记录优先于搜索结果。不同来源冲突时，保留冲突，不用猜测强行合并。

## 二、来源日志字段

每一条真正影响生成的资料都登记一行：

```text
source_ref：SRC-001
等级：S1 / S2 / S3 / S4 / S5
标题：
作者/机构：
URL 或 DOI：
访问日期：YYYY-MM-DD
版本/发布日期：
提炼的事实或方法：用自己的话写，不能粘贴长段原文
影响的项目字段：人物 / 场景 / 分镜 / 模型 / 后期 / 版权
改写或适配说明：
许可/商业使用备注：
核验状态：已核验 / 待核验 / 不采用
```

不得编造 URL、作者、书名、版本号、测试结果或“官方建议”。找不到原始来源时写“未找到原始来源”，并降低置信度。

## 三、知识库驱动的人物生产

人物不是由一条漂亮提示词决定，而是由可追溯的字段决定。每个角色都要绑定唯一 `character_id`，并把以下字段分开：

1. **事实锁**：用户明确给出的身份、年龄段、时代、关系、授权、参考图来源。
2. **视觉锁**：脸部锚点、发型、肤色/特殊标记、身高体型、服装材质、道具形状和颜色。
3. **表演锁**：常用情绪、动作习惯、视线、语速/停顿和禁止的表演变化。
4. **生成变量**：景别、姿态、动作、光线、天气、场景、画幅和目标模型。
5. **未知项**：没有证据的字段必须写 `待确认`，不能用模型猜测填入事实锁。

人物卡、概念设定表、三视图、表情图、场景入镜图和 prompt pack 都要回写：

```text
character_id：
knowledge_ref：[concept-setting.md, character-consistency.md]
source_ref：[SRC-001, SRC-002]
事实锁：
视觉锁：
表演锁：
生成变量：
未决问题：
置信度：高 / 中 / 低
```

生产闸门依次为：

`来源/授权可追溯 → 角色字段完整 → 计划表通过 → 三模型候选 → 三视图/表情图 → 场景入镜图 → 一致性 QC → 视频镜头`。

任何闸门失败，都只修正对应阶段，不把失败图片当成下一阶段的标准参考。

## 四、给理科背景用户的文意转换

输出不要只给“文学化提示词”。至少保留三栏：

| 层级 | 目标 | 必须写什么 |
|---|---|---|
| 文意层 | 确认用户真正想表达的故事和情绪 | 原意、叙事目的、角色目标、情绪变化 |
| 工程层 | 让人可以检查和复现 | 对象、属性、关系、动作起点/终点、时长、强度、单位、允许变化、验收条件 |
| 模型层 | 让目标模型容易识别 | 固定段、变量段、镜头段、负面段、参考图和参数 |

转换规则：

- 把“自然”“高级”“有电影感”“很有气质”拆成光线方向、色温、景别、镜头运动、材质、节奏、留白和表演等可观察属性；保留原意，但不把这些词当作可验证结果。
- 把“快一点”“压迫感”“关系暧昧”转换成时间范围、距离/视线、动作频率、停顿、构图和声音层级，并列出验收条件。
- 把“像某人/某作品”改为脸部或画面属性清单；不复制明星脸、角色名、原作台词或在世艺术家的独特风格。
- 数字、比例、时间、分辨率、帧率、音量和色彩空间使用明确单位；没有单位就写 `待确认`。
- 中文理解版、结构化工程版和英文/目标模型版必须逐项对应；新增内容只能标为“假设”或“模型适配”，不能伪装成用户原意。

示例：

```text
文意：她看起来很有气质，但不能太成熟。
工程：角色 ID=A3D-001；年龄锁=21 岁；表演=动作克制、肩颈放松、视线稳定；镜头=中近景；禁止=明显老年化妆、过深法令纹、成熟职场服装。
模型：21-year-old original anime-style 3D game character, calm restrained expression, relaxed shoulders, stable eye line, medium close-up ... negative: aged appearance, deep nasolabial folds, mature business outfit ...
验收：年龄感仍为青年；脸部锚点、头身比和服装没有漂移；表达“克制”而不是“呆滞”。
```

## 五、提示词不明确时的反问规则

先检查歧义是否会改变以下任一项：人物身份、真人/版权授权、年龄、剧情因果、时长节奏、画幅平台、模型输入、成片用途。如果会，暂停生成，提出最少的定向问题，并说明每个选项会改变什么。例如：

```text
我需要确认 3 点再生成：
1. “参考本人”是保留气质做原创角色，还是要做本人肖像？这会改变授权与换脸流程。
2. “短视频”目标是 9:16 还是 16:9？这会改变构图和导出规格。
3. “快节奏”是镜头平均 1–2 秒，还是对白密度更高？这会改变节拍表。
```

如果歧义只影响低风险措辞，可列出编号假设，使用 `假设 A` 继续生成，并在计划表中要求用户确认；不能默默替用户决定版权、真人身份、商业范围或关键剧情。

## 六、在线检索与提示词案例复用

用户允许或任务确实需要时，按以下顺序检索：

1. 先写检索目的，例如“确认当前模型是否支持角色参考图”或“寻找公开的三视图提示词字段结构”，不要无目的搜集长提示词。
2. 优先使用官方文档、标准、出版机构/作者页和公开可靠教学材料；记录访问日期，因为模型和平台规则会变化。
3. 阅读案例时只提炼字段顺序、变量类型、评价方法和失败规避；用本项目的角色 ID、原创设定和自己的语言重新组合。
4. 逐条检查是否带有版权角色、商标、明星脸、在世艺术家风格、原文台词、付费内容或不明来源；有风险的案例不采用。
5. 把 `source_ref`、适配后的片段、适配原因和未采用原因写入来源日志；无法核验的资料只能作为灵感，不得进入事实锁。

“复用”在本 Skill 中只表示复用方法和字段结构，不表示复制他人的长提示词、整套模板、书籍原文或受保护表达。

## 七、方法边界与停止条件

- 资料库帮助做可追溯的创作决策，不替代法律、医学、心理或安全专业意见。
- 不把模型生成的引用、搜索摘要或其他项目的角色设定当成事实。
- 不把不确定的审美判断写成客观结论；用“建议、假设、待确认、已验证”区分证据强度。
- 不为规避检测、隐藏来源、冒充真人或制造虚假证据提供方法。
- 授权不明、真人未同意、未成年人换脸、可能造成欺骗/诽谤/隐私侵害，或来源无法核验且会影响关键资产时，停止相关生成，说明缺口并改为原创虚构方案或等待授权。

最终交付前，必须能回答：这个人物字段来自哪里？哪些是用户事实，哪些是创作假设？哪份知识库规定了生产步骤？哪个来源支持模型/格式判断？每个答案都要能回指 `knowledge_ref` 或 `source_ref`。
