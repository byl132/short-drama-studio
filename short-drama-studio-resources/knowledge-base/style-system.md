# 视觉风格识别、定位与锁定

本模块只负责把“怎么拍、怎么看起来”变成可复用的视觉语言。它不替主体、场景或道具决定具体事实；这些内容通过资产 ID 在镜头阶段组合。

## 1. 统一输出头

每次开始或更新风格方案，先写：

```yaml
project_id: PROJECT-001
style_id: STYLE-001-v01
status: 待确认
knowledge_ref: style-system.md
source_ref: SRC-001
rights_status: 用户自有 / 已获许可 / 公版待核验 / 虚构原创 / 授权不明
assumptions: []
open_questions: []
```

风格只有在用户确认方向且通过一致性验收后才可标记为 `已锁定`。`已锁定`不是“生成了一张好看的图”，而是后续主体、场景、道具和镜头都能复用同一组视觉约束。

## 2. 两种工作模式

### 模式 A：直接给出三套风格方向

当用户已经说清题材、用途或大致审美时，直接给出 `DESIGN-A / DESIGN-B / DESIGN-C`。三套必须在视觉逻辑上有明显差异，不能只是换几个颜色：

| 字段 | 必须回答的问题 |
|---|---|
| 画面类别 | 写实、纪实、二维、三维、定格、广告、实验影像等 |
| 材质形态 | 皮肤、金属、玻璃、纸张、布料、颗粒、笔触、渲染方式 |
| 题材视觉语法 | 工业、生活、科幻、悬疑、喜剧等如何转成画面属性 |
| 氛围 | 明确由色温、对比度、空气感、构图和节奏造成的情绪 |
| 参考特征 | 只写可观察的镜头、材质、光线和构图，不把作品名当提示词 |
| 色调 | 主色、辅色、饱和度、明度、冷暖关系 |
| 光线 | 主光方向、光质、反差、轮廓光、环境反射 |
| 镜头 | 景别、角度、焦段感、景深、稳定/手持、焦点转移 |
| 交付风险 | 文字、复杂反射、低照度、快速动作、角色肤色等风险 |

每套方向都要给出适用原因、不可接受的变化和制作风险，便于用户作出选择。

### 模式 B：逐步确认视觉变量

当用户只说“高级、电影感、好看、未来感”等模糊表达时，按影响最大的变量提问，不一次抛出无关的问卷：

1. 画面类别与媒介：真人感、动画感、CG、绘画或混合；
2. 材质与题材：哪些表面、空间和文化语法必须被看见；
3. 氛围与情绪：观众应感到什么，靠什么视觉证据实现；
4. 参考边界：喜欢参考中的哪些可观察特征；
5. 色彩与光线：主辅色、冷暖、反差、光源方向；
6. 镜头语言：景别、机位、运动、焦段感和景深；
7. 平台与输出：画幅、分辨率、观看距离和压缩容错。

只要某个未决问题会改变画面类别、色彩逻辑、光源方向、版权边界或平台输出，就先停在 `待确认`，不能让后续模块把假设当成固定风格。

## 3. 固定项、可变项、禁止项

### 固定项

至少锁定：画面类别、材质基调、主辅色关系、整体对比度、主光方向和光质、镜头语言、画面质感、后期锐度/颗粒逻辑。

### 可变项

单镜头景别、构图、焦段、局部光线强度、天气造成的反射、特定场景的局部色彩和剧情需要的短时光照变化。

### 禁止项

未经确认不得改变核心画面类别、主辅色关系、整体光质、时代/文化视觉逻辑、参考特征边界或已锁定资产的镜头语言；不得在风格提示词里偷偷加入具体人物、地点、道具或剧情动作。

## 4. 参考作品的安全转译

参考电影、摄影、广告、动画或艺术作品时，先写“参考了什么可观察特征”，再写“如何原创改写”：

```text
参考对象（记录来源与授权）→ 可观察特征 → 本项目改写 → 不采用的受保护元素
```

可提炼的特征包括色温、对比度、颗粒、锐度、焦段感、构图、材质、光线方向、景深、运动方式和剪辑节奏。不要把在世艺术家、导演、具体影视角色、明星脸或作品名称直接写进成片提示词；不要复制原作画面、台词、Logo 或独特角色设计。

## 5. 方案与模型候选

`DESIGN-A/B/C` 是创意方向，回答“可以怎么设计”；用户确认一个方向后，才建立 `MODEL-A/B/C`。模型候选必须共用同一组已锁定风格字段，只改变模型、版本、参考图方式或适配参数，并记录：

- 模型与版本、生成日期、尺寸和参数；
- 使用的风格参考和授权状态；
- 稳定性、风格匹配、材质表现、文字/Logo 缺陷和后期成本评分；
- 选中或淘汰理由。

不能把三套创意方案当成三套模型结果，也不能把单张最惊艳的图直接当主版本。

## 6. 风格提示词结构

最终风格提示词保持“视觉语言独立”，推荐顺序：

```text
画面类别 + 材质/质感 + 色彩/对比度 + 光线逻辑 + 镜头语言 + 景深/颗粒/后期
```

镜头阶段再把 `STYLE_ID` 与主体、场景、道具 ID 组合；不要把角色姓名、具体地点、具体道具或动作写进风格固定段。

负面段至少覆盖：风格漂移、主辅色倒置、光向冲突、材质错误、过度锐化、塑料质感、无理由的复古滤镜、乱码、Logo、水印和未授权参考元素。

## 7. 风格测试与验收

锁定前至少用同一风格字段测试四类画面：

1. 空间全景：检查空间层次、色彩关系和光向；
2. 主体中景：检查人物/物体与风格的融合，不把主体事实写回风格；
3. 材质近景：检查皮肤、金属、玻璃、布料等目标材质；
4. 低照度或高反差场景：检查暗部、轮廓和压缩后的可读性。

验收顺序为：故事可读性和空间连续性 → 风格固定项 → 主体/道具关系 → 材质纹理和审美。任一固定项不稳定，状态回退到 `待复核`，不进入批量镜头。

## 8. 交接给场景和主体模块

交接内容至少包括：`STYLE_ID`、版本、已锁定的固定/可变/禁止项、主模型/备份模型、模型参数、提示词版本、参考与授权日志、风格测试文件及未决问题。主体和场景只能继承这些字段，不能在自己的提示词里改写风格母版。
