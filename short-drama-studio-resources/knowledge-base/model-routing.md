# 三模型路由与候选管理

## 一、选择策略

一次批量至少选 3 个不同模型或模型家族。优先选择能力取向不同的组合，例如：角色参考一致性强的模型、写实细节强的模型、风格化或可控性强的模型。具体名称和版本必须以当前可用工具为准，不在知识库中硬编码易过期的服务信息。

如果当前环境只有一个图像模型：

- 不伪造“三模型结果”；
- 用同一模型的 3 个明确不同版本/工作模式，并标记为“同模型多配置”，或输出另外两种模型家族的可复制提示词；
- 在交付中明确哪些是已生成、哪些是待执行。

## 二、统一批量协议

三套候选必须使用相同角色固定段、同一画幅比例、相近构图和相同资产要求。允许变化的只有模型适配语法、参数和必要的参考图控制。每套至少包含：

```text
character-sheet-3view.png
character-expression-board.png
character-in-scene.png
```

建议额外生成全身立绘，便于服装和体态锁定，但不能用额外立绘替代三视图、表情图或场景入镜图。场景入镜图要使用已锁定场景，作为进入视频生成前的连续性门槛。

## 三、文件命名

```text
{character-id}_{model-family}_{version}_3view_{date}.png
{character-id}_{model-family}_{version}_expressions_{date}.png
```

文件名、元数据和提示词中的角色 ID 必须一致。选中的主版本复制到 `selected/`，保留未选中的候选和评分，便于回溯。

## 四、比较顺序

1. 正面到侧面是否还是同一人；
2. 六种表情是否保持身份锚点；
3. 服装、配件、手部和头身比是否可控；
4. 放入三种景别和两种光线后是否稳定；
5. 是否需要大量修图或换脸才能使用。

只有通过前四项的候选才进入审美比较。记录失败原因，例如“侧脸鼻梁漂移”“表情图发型变化”“眼镜在背面消失”，而不是只写“不好看”。
