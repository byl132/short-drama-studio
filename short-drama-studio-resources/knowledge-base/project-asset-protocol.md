# 项目视觉生产交接协议

本协议把剧本、风格、主体、场景、道具、镜头和后期放进同一条可追踪的资产链。它是项目级规则，不替代各模块的专业细节；发生冲突时，用户已经确认的事实和授权边界优先。

## 1. 输入分流

先判断用户交来的是什么：

- 只有一句话创意、主题或设想：进入剧本创作流程；
- 已有故事大纲：提取最小故事输入包，补问会改变结果的问题；
- 已有完整剧本：先做剧本拆解，不重新编造剧情；
- 只要求改镜头、场景、对白或结尾：进入局部修改模式，列出因果和资产影响；
- 只要一个测试画面：可以跳过完整剧本，但仍要建立最小资产记录和授权状态。

## 2. 唯一资产顺序

```text
SCRIPT → SCRIPT BREAKDOWN → ASSET MASTER → STYLE → SUBJECT → SCENE → PROP → SHOT → VIDEO / POST
```

在资产生产层，统一使用 `STYLE → SUBJECT → SCENE → PROP → SHOT`。课程编号只是教学顺序，不代表每次项目都要机械重跑；后续模块只能继承已经确认的字段，不能偷偷改写锁定字段。

## 3. ID、版本和关系

每个项目至少建立以下稳定 ID：

```text
PROJECT-001
SCRIPT-001-v01
STYLE-001-v01
SUBJECT-001-v01
SCENE-001-v01
SCENE-001-VAR-01
PROP-001-v01
SHOT-001-v01
```

每项资产记录：`parent_id` 或 `variant_of`、`source_ref`、`knowledge_ref`、`rights_status`、`version`、`status`、`input_refs`、`output_refs`、`model`、`model_version`、`prompt_version`、`qc_status` 和 `selected_reason`。

## 4. 信息分类

- `SCRIPT FACT` / `FACT`：用户或剧本明确给出的事实；
- `PREFERENCE`：审美、平台或制作偏好；
- `INFERENCE`：有依据的合理推断，不能写回成剧本事实；
- `DESIGN`：需要视觉或制作补充的设计；
- `ASSUMPTION`：为了继续工作暂时采用的假设；
- `OPEN QUESTION`：会改变资产、授权、时长或剧情的问题。

未决的高影响问题未解决前，不锁定受影响资产。冲突时列出冲突字段，不用猜测消除冲突。

## 5. 资产字段和方案分层

每个风格、主体、场景、道具和镜头都要写清：

- 固定项：跨镜头不能随意改变；
- 可变项：允许因剧情、状态、镜头或天气变化；
- 禁止项：生成时必须避免的漂移；
- 依赖项：必须读取的其他资产；
- 验收项：人或机器可以直接检查的标准。

`DESIGN-A/B/C` 表示三种创意方向，回答“可以怎么设计”；`MODEL-A/B/C` 表示同一已确认方向在不同模型或模型家族下的候选，回答“哪套更稳定”。二者不能混称。

## 6. 状态和停止门槛

状态只使用：`待确认 / 待检索 / 待生成 / 待复核 / 已锁定 / 已阻塞`。变体使用 `variant_of`，更新写入版本和变更记录，不单独创造“变体”或“已更新”状态。

出现以下情况，暂停批量生成：

- 核心资产没有 ID、来源或授权状态；
- 用户事实与已有设计冲突；
- 固定字段尚未锁定；
- 主要角色缺三视图、6 格表情图或场景入镜图；
- 场景、道具和镜头引用关系不完整；
- 计划表没有输入、输出、验收条件或失败回退；
- 真实人物、品牌、Logo、影视片段或原作台词的授权不明。

## 7. 剧本更新机制

剧本是叙事事实源。剧本、风格、主体、场景或道具变化时：

1. 找到受影响的资产 ID 和镜头 ID；
2. 区分剧本更新、用户新意图和原设计错误；
3. 标记冲突字段，暂停受影响资产；
4. 记录 `SCRIPT DIFF`，只更新受影响资产；
5. 重新执行对应 QC，保留旧版本，不覆盖历史记录。

## 8. 最终交接包

最终至少能回溯到：剧本版本、资产总表、场次—资产矩阵、风格锁定卡、角色三视图/表情图/场景入镜图、场景和道具状态图、镜头提示词、模型候选、来源授权日志、QC 记录、生产计划和未决问题清单。
